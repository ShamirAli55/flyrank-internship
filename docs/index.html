Search Intelligence: Predicting Content Performance Decline

Author: Shamir Ali

Lane: Refresh / Content Opportunity Scoring

Project: FlyRank ML Internship

Abstract

This project asks whether search-performance signals can be used to identify content that is likely to experience a significant decline in impressions. The analysis uses the FlyRank internship warehouse and combines monthly impression data with query-level signals. A Random Forest classifier was trained using a client-grouped train/test split and evaluated on held-out clients. The model achieved an F1 score of 0.47, with precision of 0.53 and recall of 0.42 for the decline class. The resulting ranking is intended as decision-support for content review and prioritization rather than as a causal explanation of search ranking behavior.

1. Introduction

Content teams need to decide which pages should be reviewed or refreshed first. Reviewing every page equally is inefficient, so a useful system should help prioritize pages using measurable search-performance signals.

The decision supported by this project is: which content pages should receive attention because their search visibility may be declining?

The unit of analysis is a content page. The output is a ranked list based on the model's estimated probability of an impressions decline. A human editor can use this ranking to decide which pages should be reviewed first.

A wrong recommendation can waste editorial effort or cause a genuinely important page to be missed. This is why the model is treated as a prioritization tool rather than an automatic decision maker.

2. Data

The project uses the FlyRank ML Internship dataset from the FlyRank/internship-warehouse release.

The main source used was the daily content-performance table. Monthly content-level impressions were calculated for February 2026 and March 2026. Query-level signals were also used from the 90-day content-query data.

Features Used

Feature Description
prev_month_impressions Content impressions in the previous month.
visible_queries Number of visible search queries associated with the content.
rare_share Share of impressions associated with rare queries.
anon_share Share of impressions associated with anonymized queries.
top_query_share Share of retained impressions contributed by the highest-impression query.

Client and content identifiers were used for grouping and joining where required, but were not used as predictive features.

Label-derived fields and future outcome information were not used as model features. The analysis also avoids exposing client names, domains, URLs, private queries, or other identifying information.

3. Methodology

Target Definition

A content page is labelled as declining when its current-month impressions are less than 80% of its previous-month impressions.

In other words, the target represents an impressions decline of more than 20%.

Baseline

The baseline is a simple visibility-based rule. Pages with at least 1,000 impressions and an average position between 4 and 15 receive a high-visibility priority score. Other pages are assigned lower priority.

The baseline was intentionally kept simple so that it provides a transparent reference for the model.

The baseline produces an action score and recommendation rather than the same binary prediction used by the Random Forest. Therefore, a directly comparable classification metric was not reported for the baseline.

Model

A Random Forest classifier was selected because it can model non-linear relationships between search signals and can provide feature-importance estimates for interpretation.

Validation

The data was split using GroupShuffleSplit with clients as groups. 80% of the data was used for training and 20% for testing, with a fixed random seed of 42. Clients appearing in the test set were not used for training.

This provides a more realistic test of whether the model can generalize to clients it has not seen during training.

4. Results

The Random Forest was evaluated on the held-out client-grouped test set.

Metric Random Forest
Accuracy 0.649
Precision 0.531
Recall 0.422
F1 Score 0.471

For the decline class, the model correctly identified approximately 42% of the actual declining cases in the test set and had approximately 53% precision.

The target was imbalanced, so accuracy alone does not fully describe model performance. Precision, recall, and F1 were used to evaluate performance on the decline class.

The baseline was retained as a transparent rule for comparison of the decision approach, but no directly comparable classification score is reported because its output is a priority score rather than the same binary prediction task.

5. Limitations & Honest Framing

  • The model identifies statistical patterns in the available data; it does not establish causation.
  • The model does not predict or reproduce Google's ranking algorithm.
  • Search intent, seasonality, content quality, and other factors are not fully represented.
  • The baseline is intentionally simple and is based mainly on visibility and position.
  • The model's recommendations require human review before an editorial action is taken.
  • The evaluation uses a specific time window and should not automatically be treated as evidence that the same performance will hold in every future period.
  • The model was evaluated on a held-out client split, but this does not guarantee performance on all future clients or time periods.

The results are therefore best described as observed and directional decision-support evidence.

6. Ranked Recommendations

The model produces a ranking based on the estimated probability that a content page belongs to the impressions-decline class.

For operational use, the scores can be grouped into the following review priorities:

Priority Model Probability Recommended Action
High ≥ 0.70 Review for Content Refresh
Medium 0.50–0.69 Monitor and consider review
Low < 0.50 Low priority / monitor

These thresholds are operational categories for prioritization and were not presented as statistically validated cutoffs.

Suggested Editorial Workflow

  1. Start with pages receiving the highest model scores.
  2. Check whether the page has actually experienced a meaningful performance decline.
  3. Review recent content changes and search intent.
  4. Decide whether the page should be refreshed, monitored, or left unchanged.

These recommendations are prioritization suggestions, not automatic content decisions.

8. Reproducibility

The analysis was developed in Python using DuckDB, pandas, NumPy, and scikit-learn. The Random Forest used 200 estimators with random seed 42 and parallel processing.

The capstone notebook contains the data preparation, feature construction, grouped train/test split, model training, evaluation, feature interpretation, and recommendation ranking.

To reproduce the work, clone the repository, install the required Python dependencies, provide the required Hugging Face dataset access, and run work/notebooks/capstone.ipynb from top to bottom.
